A trilha da aula

Crie a página de um evento fictício, teste no navegador, registre duas versões e publique.

  1. Preparar a conta
  2. Planejar a página
  3. Criar e testar
  4. Revisar segurança
  5. Registrar as versões
  6. Publicar no Pages
Etapa 1 de 6

Prepare sua conta no GitHub

O GitHub guarda seus arquivos e o histórico das mudanças. Você usará sua conta quando chegar a hora de publicar.

  1. Crie sua conta ou entre na conta que já tem. Escolha um nome de usuário que você possa mostrar publicamente e confirme seu e-mail.
  2. Revise o que aparece no seu perfil. Nas configurações de e-mail, use a opção Keep my email addresses private para que as edições feitas no site do GitHub usem o endereço noreply.
  3. Configure a autenticação em dois fatores e guarde os códigos de recuperação em local privado. Em computador compartilhado, saia da conta ao fim da aula.

Se o cadastro estiver pendente, comece pelo modelo no laboratório e acompanhe a publicação com o professor.

Etapa 2 de 6

Transforme sua ideia em um pedido

No vibe coding, você descreve a ideia em linguagem natural, pede ajuda à IA e testa a resposta. Comece com um briefing curto que defina o tema, o público e a ação principal da página.

Um pedido que dá para conferir. “Crie um index.html para um clube fictício. Inclua um título, três atividades e um link para a programação que funcione com clique e teclado.”

Escolha o essencial para a primeira versão. Use o prompt de planejamento e escreva um teste observável, como ler a programação no celular sem rolar para os lados.

Etapa 3 de 6

Crie e teste no navegador

O HTML organiza o conteúdo. O CSS cuida da aparência. O JavaScript pode acrescentar comportamentos, mas um link para outra parte da página funciona só com HTML.

  1. Use o prompt para gerar a página ou comece pelo modelo do Clube de Ideias.
  2. Cole o código em um editor de texto simples. Salve como index.html, em UTF-8, e abra no navegador. Confira se o editor anexou .txt ao nome.
  3. Clique em Ver programação. Depois, chegue ao link com Tab e use Enter. Reduza a janela e confira se a agenda cabe na tela.

Algo saiu diferente do esperado? Informe à IA o arquivo, o trecho relevante, o que aconteceu e o que deveria acontecer. Use o exercício do link quebrado para praticar.

Etapa 4 de 6

Revise antes de enviar

O navegador recebe o código de uma página estática. Em um repositório público, qualquer pessoa pode consultar os arquivos e as versões anteriores.

  • Use nomes e horários inventados. Confira se o arquivo e o chat estão livres de dados pessoais, senhas, tokens, chaves de API e arquivos .env.
  • Confira para onde cada link leva e revise os scripts que a IA sugeriu. Peça uma explicação para qualquer trecho que você ainda não entenda.
  • Um chat pode sugerir código para você colar. Um agente também pode editar arquivos ou executar comandos quando tem permissão. Confira o que ele pretende alterar e autorize apenas o necessário.

Se uma credencial for exposta, revogue ou substitua a credencial no serviço que a emitiu e avise o professor. Apagar o texto da versão atual deixa as versões antigas no histórico.

Etapa 5 de 6

Registre suas duas versões

Git registra mudanças. GitHub é o serviço que hospeda projetos com esse histórico. O repositório reúne o código e suas versões. A branch é uma linha de trabalho, geralmente chamada main no início. O commit registra uma mudança e o diff mostra as linhas que mudaram.

  1. Crie um repositório público de exercício como meu-primeiro-site. Adicione um README na criação para iniciar a branch principal.
  2. Abra Add file → Upload files e envie index.html na raiz, fora de pastas. Registre o primeiro commit com uma mensagem como Cria página do evento. Você já pode iniciar a publicação no Pages e voltar para fazer a melhoria enquanto aguarda.
  3. Altere uma coisa, como o título ou o espaçamento da agenda. Os prompts de melhoria e de refinamento visual ajudam a definir a mudança e o teste. Teste localmente. No GitHub, abra o arquivo, clique no lápis, aplique a edição testada e use Commit changes na mesma branch. Escreva uma mensagem que descreva a mudança.
  4. Abra History na página do arquivo, selecione o último commit e compare as linhas. Para recuperar um trecho, consulte a versão anterior, copie o trecho desejado para o arquivo atual e faça um novo commit.
Etapa 6 de 6

Publique no GitHub Pages

Você testou um arquivo local e guardou sua versão no repositório. Agora o deploy publica esse código em um endereço que a turma consegue abrir.

  1. No repositório, acesse Settings → Pages. Em Build and deployment, selecione Deploy from a branch.
  2. Escolha a branch que contém o arquivo, normalmente main, escolha /(root) e clique em Save.
  3. Veja o andamento em Actions. Em Settings → Pages, clique em Visit site para obter o endereço publicado.
  4. Depois de registrar o segundo commit e aguardar o deploy, abra o endereço em janela anônima, confira a mudança e teste o link da programação. A atualização pode levar alguns minutos. Anote o endereço para a entrega.

Consulte o guia oficial do GitHub Pages.

Por que o link não funciona?

Teste “Ver programação” e compare o destino no atributo href com o id do título. Conte o que observou antes de revelar a correção.

Código com erro

<a href="#agenda">Ver programação</a>
<h2 id="programacao">Programação</h2>

Teste no navegador

Acione o link para conferir o que acontece.

  1. O que a página deveria fazer?
  2. O que fez?
  3. Como você provou que voltou a funcionar?
Revelar a correção

O navegador procura um destino com o mesmo nome que vem depois de #. Ao trocar #agenda por #programacao, os dois nomes passam a coincidir.

Código corrigido

<a href="#programacao">Ver programação</a>
<h2 id="programacao">Programação</h2>

Para continuar

O mesmo projeto na Vercel

Importe o repositório do exercício para experimentar outro endereço de publicação.

Ver passos da Vercel
  1. Abra a página de novo projeto da Vercel, entre com sua conta, conecte o GitHub e importe o repositório da aula. Leia as permissões e selecione apenas esse repositório se a opção estiver disponível.
  2. Para um index.html estático na raiz, selecione Other no campo Framework Preset. Mantenha a raiz do projeto e o Build Command vazio. Use Override se precisar definir o campo manualmente.
  3. Selecione Deploy. Quando a publicação terminar, abra o domínio de Production e teste em janela anônima. Se falhar, abra Deployments, escolha a tentativa e leia os registros da publicação.

Preview é um endereço para conferir uma alteração antes de levá-la ao público. Production é o endereço da versão publicada para visitantes. Para ver essa diferença, experimente uma alteração em outra branch depois da aula.

Dúvidas comuns

Travou em alguma etapa?

O arquivo abre como texto

Mostre as extensões de arquivo e confira se o nome termina em index.html. Se for index.html.txt, salve como “Todos os arquivos” no editor, mantenha a extensão .html e abra com o navegador.

Vejo erro 404 no GitHub Pages

Em Settings → Pages, confira a branch e a pasta selecionadas. A pasta publicada deve conter index.html em letras minúsculas. Em Actions, veja se a publicação terminou e abra a URL em Visit site.

Minha alteração ainda não apareceu

Confira se o novo commit entrou na branch usada pelo Pages. A publicação pode levar até 10 minutos. Depois que terminar, recarregue a página ou teste em janela anônima. Ajuda do GitHub Pages

O projeto não aparece na Vercel

Confira se você entrou com o GitHub correto e se a integração tem acesso ao repositório do exercício. Depois, volte para a importação e procure o nome do repositório.
